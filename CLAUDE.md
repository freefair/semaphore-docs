# Documentation working agreement

Publish all documentation as directly readable GitHub-flavored Markdown.
The canonical entry point is `README.md`, with the manual under `docs/` and translations under `translations/<locale>/`.
Use relative links ending in `.md`, ordinary headings, blockquote callouts and local images.
Keep anchor syntax out of visible headings; use a separate standard HTML anchor only when preserving an existing deep link.
Keep all page indexes current and run `node scripts/check-docs.mjs` after changes.

Reading documentation requires no compilation, generated site, JavaScript application or external configurator.
Configuration and CLI references are checked-in Markdown generated by the product repository's optional maintainer tools.
Edit `tools/docsref`, `tools/clidocs` or `tools/apidocs` in that repository, then commit their regenerated output here.
Reviewed descriptions in `tools/docsref/descriptions.json` may clarify or correct source comments; verify them against consumers.

Semaphore EX is one full-featured product. Describe actual enablement and permissions, and identify unsupported providers explicitly.
For translated pages that lack reviewed fork content, link explicitly to canonical English guidance rather than recreating a website fallback.
Avoid links to the upstream vendor website; use local guides, local assets and the fork's source or release repository.
